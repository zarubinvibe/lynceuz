Спасибо, что заглянули. Линкей маленький намеренно, поэтому планка для нового
кода упирается в доказательства: изменение должно быть проверяемым и не должно
расширять то, до чего инструменту разрешено дотягиваться.

## До того как писать код

Прочитайте [AGENTS.md](AGENTS.md). Там лежат инварианты, и pull request, который
ломает хотя бы один, будет закрыт, каким бы хорошим ни был код. Коротко: нулевая
денежная цена, только публичные цели, никакой новой зависимости в рантайме и
честный отказ вместо выдуманного результата.

## Разработка

```bash
git clone https://github.com/zarubinvibe/lynceuz.git
cd lynceuz
node scripts/onboard.mjs --selftest   # инструмент проверяет сам себя
npm test                              # весь набор, интернет не нужен
npm run check                         # синтаксис по src/
```

`npm test` обязан закончиться нулем падений и нулем пропущенных тестов.
Пропущенный тест считается упавшим: он ничего не доказывает и прячет причину.

## Как выглядит хороший pull request

- Одно изменение, описанное простыми словами в теле.
- Тест, который падает до вашей правки и проходит после. Новое сетевое поведение
  без враждебного теста не принимается.
- Никакой новой зависимости в `package.json`. Считаете, что без нее нельзя,
  заведите сначала issue и скажите, что она дает.
- Существующие тесты не трогаем. Если тест неверный, объясните почему в pull
  request, а не переписывайте его молча.

## Путь

```text
fork -> ветка -> commit -> push -> Pull Request
```

Сообщения коммитов в виде `тип: описание`: `feat`, `fix`, `refactor`, `docs`,
`test`, `chore`.

## Куда писать о проблеме

Ошибки и вопросы идут в [Issues](https://github.com/zarubinvibe/lynceuz/issues).
То, что можно использовать против пользователя, идет через
[SECURITY.ru.md](SECURITY.ru.md), а не публичным issue.
