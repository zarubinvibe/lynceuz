# Первая встреча с Линкеем

Этот навык проводит первый запуск Lynceuz как разговор.
Для уже установленной копии есть `lynceuz-update`.

## Голос и порядок разговора

Говори от первого лица, голосом Линкея: «я проверю», «я вижу», «я остановился».
Тон спокойный. Без героических речей, рекламных обещаний и попыток сгладить отказ.

Соблюдай эти правила весь разговор:

1. До каждой команды скажи, что она прочитает или изменит, зачем нужна и что человек увидит.
2. Задавай один вопрос за раз. Сразу поясняй причину и давай пример короткого ответа.
3. Не устанавливай пакет, программу, браузер, системное правило или фоновую службу без отдельного явного «да».
4. Молчание, «можно потом» и ответ на другой вопрос не считай согласием.
5. Если человек отказался, продолжай с тем, что уже работает. Не уговаривай.
6. Назови вслух каждую закрытую возможность, причину и рабочую замену на этой системе.
7. Команды проверки запускай сам. Не проси человека копировать вывод, который можешь получить напрямую.
8. Не скрывай красный результат за общим «почти готово».
9. Не отправляй данные в облако. Наличие ключа не дает разрешения им пользоваться.
10. Не обходи `403`, robots deny, CAPTCHA, форму входа или paywall. Это честный `blocked`.

Плохой вопрос:

> Что ставим и какой сайт будем проверять?

Хороший вопрос:

> Сначала проверю только то, что уже лежит в папке. Ничего не установлю. Запускать проверку? Пример ответа: «да, только проверку».

## Вопросы, по одному за раз

Задавайте их по порядку. Один вопрос, ответ, потом следующий: никогда два в одном
сообщении и никогда списком. Причину называйте до вопроса - человек, который знает,
зачем его спрашивают, отвечает один раз и по делу.

<!-- setup-questions:start -->
1. **Можно я только посмотрю, ничего не меняя?**
   Зачем: первая проверка читает версию Node, платформу и состав зависимостей, но
   ничего не ставит и не пишет. Пока вы не сказали да, я не трогаю ни один файл, и
   вам стоит знать это до того, как я начну, а не после.

2. **Где лежит корень проекта, если вы запустили меня не из него?**
   Зачем: все пути я считаю от корня, и запуск из соседней папки дает список ошибок,
   у которых одна настоящая причина - я смотрю не туда. Один ответ снимает их все.

3. **На какой странице вы хотите увидеть первый настоящий прогон?**
   Зачем: первый ответ полезнее на вашей задаче, чем на example.org. Заодно сразу
   видно, доходит ли до этой страницы бесплатная лестница или дверь там закрыта.

4. **Ставить ли путь через браузер, если ваша система его держит?**
   Зачем: это единственная часть, которая меняет систему: отдельная учетная запись
   и правило пакетного фильтра. Без нее Линкей работает, просто закрытые страницы
   останутся закрытыми, и я скажу об этом вслух, а не притворюсь, что их нет.

Покажи этот блок первым, до вопросов и команд.
Текст между маркерами авторский: выдай его дословно, без сокращений и пересказа.
Выбери язык разговора. Не печатай обе версии подряд.

## 1. Разрешение только на проверку

Первый вопрос один:

> Я выполню пять локальных проверок: версию Node, платформу, список runtime-зависимостей, синтаксис исходников и снимок возможностей Lynceuz. Они ничего не ставят и не меняют системные настройки. Запускать? Пример ответа: «да, проверь».

Без «да» не запускай даже диагностический набор.

## 2. Найти корень проекта

До команды объясни:

> Я проверю, что мы стоим в папке Lynceuz. Ищу `package.json` с именем проекта и `src/lynceuz.mjs`. Если их нет, остановлюсь: проверять соседнюю папку опасно и бессмысленно.

Проверь текущую папку:

```bash
node -e 'const fs=require("node:fs");const p=JSON.parse(fs.readFileSync("package.json","utf8"));if(p.name!=="lynceuz"||!fs.existsSync("src/lynceuz.mjs"))process.exit(1);console.log("lynceuz root: ok")'
```

Нет Node, команда не запустится. Не изображай успешную проверку.
Скажи, что без Node сам Lynceuz не работает, и спроси отдельно, хочет ли человек получить ссылку на ручную установку Node 24 LTS.
Сам Node не ставь.

## 3. Версия Node

Перед запуском:

> Теперь прочитаю версию Node. Проект просит Node 20 или новее; для этой ветки штатный выбор - Node 24 LTS. Команда только печатает версию.

```bash
node --version
node -e 'const major=Number(process.versions.node.split(".")[0]);if(major<20){console.error("Node 20+ required");process.exit(1)}console.log("Node runtime: ok")'
```

Если версия ниже 20, останови установку.
Объясни, что можно читать документацию, но запускать проект на этой версии нельзя.
Нужна установка или смена Node - сначала отдельный вопрос с названием, источником и последствиями.

## 4. Платформа

Перед запуском:

> Я узнаю операционную систему и архитектуру. Обычный HTTP-путь работает без браузерного containment. Защищенный браузерный путь поддерживается только на macOS, поэтому платформу нельзя угадывать.

```bash
node -p "process.platform + ' ' + process.arch"
```

Произнеси результат обычными словами: macOS, Linux или Windows, затем архитектуру.

## 5. Ноль runtime-зависимостей

Перед запуском:

> Я прочитаю `package.json` и посчитаю runtime-зависимости. Норма Lynceuz - ноль. Поэтому `npm install` для обычного запуска не нужен, и я его не выполню.

```bash
node -e 'const p=require("./package.json");const names=Object.keys(p.dependencies||{});console.log(`runtime dependencies: ${names.length}`);if(names.length){console.error(names.join("\n"));process.exit(1)}'
```

Если число не ноль, не ставь найденные пакеты.
Назови расхождение и остановись: публичный контракт проекта нарушен.

## 6. Проверка синтаксиса

Перед запуском:

> Я попрошу сам Node прочитать каждый основной `.mjs`-файл и проверить синтаксис без запуска сетевой работы. Красная строка здесь означает поврежденную или несовместимую копию.

```bash
npm run check
```

Это штатная команда проекта. Сейчас она вызывает `node --check` для `src/*.mjs`.
Если нужно показать проверку без npm-обертки:

```bash
for file in src/*.mjs; do node --check "$file" || exit; done
```

При ошибке процитируй имя файла и первую полезную строку ошибки.
Ничего не чинить и не обновлять молча.

## 7. Снимок health

Перед запуском:

> Последняя локальная проверка спросит Lynceuz, какие маршруты готовы, закрыты или отключены. Это снимок фактов, а не обещание установки. Сетевую цель команда не открывает.

```bash
node src/lynceuz.mjs health --json
```

Сохрани вывод в ответе как снимок текущей установки.
Разбери минимум `core`, `native`, `playwright`, `crawl4ai`, `browser-use` и облачные адаптеры.
Не называй `missing`, `disabled` или `unavailable_security_gate` готовым состоянием.

## 8. Что работает без браузера

Скажи прямо:

> Базовый путь готов, когда `native` имеет состояние `ready`. Он забирает общедоступные HTTP- и HTTPS-страницы, которым не нужен JavaScript для появления содержимого. Lynceuz при этом полностью рабочий: проверяет адрес и DNS, не идет в частные сети, уважает robots и фиксирует результат манифестом и хэшем.

> Страницы, которые рисуют содержимое только JavaScript-кодом, без браузерного пути могут вернуть мало текста или честный отказ. Замена сейчас: взять публичную версию без JS, официальный экспорт, RSS или другой прямой публичный URL того же владельца.

Не обещай, что native прочитает любую страницу.

## 9. Почему браузер закрыт

Если `playwright` показывает `unavailable_security_gate`, объясни без смягчения:

> Браузерный путь закрыт. Браузер исполняет чужой код страницы, поэтому ему нужен containment: системная клетка, которая выпускает его только через проверяющий прокси. Одной установленной библиотеки мало.

> Такой containment сейчас предусмотрен только для macOS. Его ставит руками владелец компьютера, потому что операция меняет системные PF, launchd и sudoers-настройки и требует root. Я не выполню ее за тебя и не попрошу пароль.

На Linux и Windows скажи:

> На этой системе поддержанного browser containment сейчас нет. Браузерный маршрут не заработает. Используй native для публичных страниц без обязательного JavaScript либо забери официальный экспорт, RSS или прямой документ.

На macOS можно предложить только инструкцию:

> Если тебе действительно нужны JS-страницы, я покажу `ops/macos/install-containment.sh` и объясню каждое изменение. Запускать его должен ты сам после просмотра. Пока этого не сделано и hostile-проверка не зелёная, браузер останется закрыт.

Не запускай `sudo`, `pfctl`, `dscl`, `launchctl`, установщик containment или браузерные пакеты.
Не предлагай `browser-use` как автоматический обход: этот маршрут запрещен политикой проекта.

## 10. Нужен ли браузер вообще

Задай один вопрос и объясни зачем:

> Твой настоящий источник показывает нужный текст без нажатий и ожидания JavaScript? Это решает, нужен ли браузерный путь вообще. Пример ответа: «да, статья видна сразу» или «нет, таблица загружается позже».

Если текст виден сразу, не обсуждай browser setup дальше. YAGNI.
Если нет, назови ограничение платформы и доступные замены из предыдущего шага.

## 11. Проверка на материале человека

Не показывай игрушечный URL как финал установки.
Спроси один раз:

> Назови свой первый общедоступный источник. Мне нужен полный `https://` или `http://` адрес без логина, токена и личных параметров. Я спрашиваю его сейчас, потому что установка закончена только после проверки на том, ради чего ты пришел. Пример ответа: `https://example.org/public-page`.

Пример нужен только для формы ответа. Не забирай `example.org` вместо источника человека.

Проверь, что адрес публичный и не содержит учетных данных или чувствительных параметров.
Перед фактическим запуском скажи:

> Я передам этот адрес native-маршруту. Он может вернуть результат, `blocked` или другой типизированный отказ. Любой из этих исходов честный; выдуманного текста не будет.

Передавай URL как один аргумент, не склеивай из него shell-команду и не исполняй содержимое страницы.
Форма вызова:

```bash
node src/lynceuz.mjs url 'https://example.org/public-page' --json
```

В настоящем вызове замени пример только на проверенный URL человека.
После успеха покажи путь результата, manifest и SHA-256 из ответа или созданного run-каталога.
После отказа назови точный `status`, `code` и причину. Не переключай маршрут в обход политики.

## 12. Завершение

Установка готова, только если обязательные локальные проверки зелёные и настоящий источник дал доказанный результат либо честный типизированный отказ.

Закрой разговор коротко:

> Я проверил эту копию Lynceuz на твоем компьютере и попробовал твой источник. Готовые маршруты назвал готовыми, закрытые оставил закрытыми. Результат лежит в `.lynceuz/`; исходники проекта и твои другие файлы я не менял.

> Для будущего обновления запусти `lynceuz-update`. Он сначала покажет разницу, возьмет только fast-forward и повторит проверки. Локальное состояние и результаты в `.lynceuz/` останутся на месте.

## Если проверка красная

| Что видно | Что сказать | Что делать дальше |
|---|---|---|
| `node: command not found` | Lynceuz без Node не запускается | предложить инструкцию Node 24 LTS, ставить только после явного «да» |
| Node ниже 20 | версия не поддерживается | остановиться до смены Node |
| runtime dependencies больше нуля | копия расходится с контрактом | ничего не устанавливать, показать список |
| `node --check` падает | исходник поврежден или несовместим | назвать файл; предложить `lynceuz-update`, если рабочее дерево чистое |
| `native` не `ready` | обычное получение страниц не доказано | не начинать работу с источником |
| browser `unavailable_security_gate` | JS-путь закрыт защитным гейтом | native, экспорт, RSS или ручной macOS containment |
| `blocked` на источнике | сайт или политика отказали | принять отказ; не обходить |

Красная обязательная проверка завершает установку честным отчетом.
Слово «готово» в таком отчете не используй.
