# Первый час с Lynceuz

<p align="center"><img src="assets/pantheon/doc-onboarding.png" alt="Линкей-дозорный прикрывает глаза ладонью рядом с запечатанным ларцом улик, поодаль стоят лестница бесплатных путей и чистый адресный камень" width="100%"></p>

Проведем тебя от пустой папки до доказанного результата. Ты вводишь команду,
читаешь, что появилось, и идешь дальше. Ни один шаг здесь ничего не ставит и не
меняет системные настройки. Если проверка загорелась красным — остановись и
разберись с ней, а не проскакивай: пропущенный красный потом все равно всплывет.

Другие языки: [English](ONBOARDING.md) · [简体中文](ONBOARDING.zh.md).

1. **Проверь версию Node.** Lynceuz просит Node 20 или новее и не тянет ни одной
   runtime-зависимости, так что это единственное обязательное условие.

   ```bash
   node --version
   ```

   Ждем что-то вроде `v24.15.0`. Если число меньше 20 или оболочка отвечает
   `command not found` — сначала поставь Node 20+, потом возвращайся.

2. **Забери код.** Склонируй репозиторий в удобную папку.

   ```bash
   git clone https://github.com/zarubinvibe/lynceuz.git
   ```

   Git покажет ход загрузки и закончит словом `done.`. Замени `OWNER` на аккаунт,
   где лежит твоя копия.

3. **Зайди внутрь папки.** Все следующие команды считают, что ты уже там.

   ```bash
   cd lynceuz
   ```

   В приглашении теперь `lynceuz`. Из этой папки мы больше не выходим.

4. **Не ставь зависимости — и это правильно.** Runtime-зависимостей нет, качать
   нечего. Запустишь `npm install` по привычке — он ответит `up to date` и ничего
   не добавит. Пустой результат здесь — это обещание проекта, а не ошибка.

5. **Запусти проверку готовности.** Это честный снимок того, что твоя машина
   умеет прямо сейчас.

   ```bash
   node scripts/onboard.mjs
   ```

   Получишь короткий отчет: версию Node, платформу, `0 runtime dependencies`,
   сколько модулей исходников прочиталось и какие возможности готовы или закрыты.
   Последняя строка `Ready: mandatory checks are green.` значит, что все нужное
   человеку на месте.

6. **Тот же снимок, но данными.** Когда нужен машинный формат — для скрипта, лога
   или отчета об ошибке — попроси JSON.

   ```bash
   node scripts/onboard.mjs --json
   ```

   Печатается объект с `"kind": "lynceuz_onboarding"` и
   `"runtime_dependencies": 0`. При любой красной обязательной проверке команда
   выходит ненулевым кодом, поэтому на нее можно опереть конвейер.

7. **Пусть скрипт проверит сам себя.** Прежде чем верить снимку, прогони его
   собственные утверждения.

   ```bash
   node scripts/onboard.mjs --selftest
   ```

   Исправная копия отвечает `onboard selftest: ok` и выходит с кодом `0`.

8. **Убедись, что исходники читаются.** Это штатная проверка проекта: Node читает
   каждый основной модуль без единого сетевого вызова.

   ```bash
   npm run check
   ```

   Пустой вывод и чистый выход означают, что исходники целы. Названный файл с
   ошибкой — поврежденная или несовместимая копия.

9. **Спроси Lynceuz, какие маршруты живые.** Снимок health перечисляет движки и
   их состояние: `ready`, `disabled` или закрыт защитным гейтом.

   ```bash
   node src/lynceuz.mjs health --json
   ```

   `native` должен быть `ready`, а браузерные движки — `unavailable_security_gate`.
   Это нормальное состояние свежей копии, а не поломка.

10. **Забери первую настоящую страницу.** Возьми публичный URL, который показывает
    текст без JavaScript. Передавай его одним аргументом в кавычках.

    ```bash
    node src/lynceuz.mjs url 'https://example.org/' --json
    ```

    При успехе получишь путь к результату, манифест и SHA-256. Если сайт
    отказал — вернется типизированный `blocked` с точной причиной, без единой
    выдуманной строки.

11. **Найди доказательство на диске.** Каждый запуск пишет артефакт и манифест в
    `.lynceuz/`, и эта папка в git не уезжает.

    ```bash
    ls .lynceuz
    ```

    В манифесте записаны движок, попытки, URL, время, хэш и предупреждения — то,
    что потом можно предъявить.

12. **Держи копию свежей через `lynceuz-update`.** Когда захочешь новую версию,
    запусти навык `lynceuz-update`. Он сначала покажет разницу, возьмет только
    fast-forward, повторит проверки и не тронет ни результаты в `.lynceuz/`, ни
    локальные настройки.

## Браузерный путь (необязательный, только macOS)

Браузерные движки исполняют чужой код страницы, поэтому остаются закрытыми, пока
владелец машины не поставит containment руками. На macOS ты можешь сам изучить и
запустить `ops/macos/install-containment.sh`; на Linux и Windows поддержанного
браузерного пути пока нет — работай через native или публичный экспорт.
`node scripts/onboard.mjs --json` показывает, что именно нужно браузерному пути.

## Поставь звезду и пришли правку

Если Lynceuz сэкономил тебе время, [поставь репозиторию звезду](https://github.com/zarubinvibe/lynceuz): так честный
бесплатный скрапер найдут другие.

Уже установлен и нужна свежая версия? Набери `/lynceuz-update` в Claude Code.
Он покажет, что изменилось, до того как что-то тронет, подтянет только fast-forward,
не тронет твои настройки и сохраненные результаты и в конце заново прогонит
собственную проверку проекта.

А если что-то улучшил, путь короткий:

**fork -> ветка -> commit -> push -> Pull Request.**

```bash
# сделай fork на GitHub, затем:
git checkout -b moya-pravka
git commit -am "docs: уточнить формулировки онбординга"
git push -u origin moya-pravka
# открой Pull Request из своего форка на GitHub
```

Держи правку небольшой и опиши, что было до и после. Понятный конкретный
Pull Request сливают быстрее всего.
